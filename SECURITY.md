# Security and sensitive-data reports

This project is in preparation and has no supported application release yet.

Use [GitHub private vulnerability reporting](https://github.com/RulerCompass1729/native-agent-workspace/security/advisories/new)
for security issues. Do not open a public issue containing credentials, session
transcripts, personal or financial records, customer data, or exploit details that
would expose other users. Start with a minimal description and synthetic steps.
Even a private report should not contain a live password, API key, or raw user dump.

For ordinary bugs, provide a small invented reproduction and version information.
Do not upload full logs, environment dumps, screenshots of real sessions, or a
copy of your private pattern file. Public reports, attachments, and commit metadata
can remain available in caches and forks after deletion.

If a credential was exposed, revoke or rotate it through its provider immediately.
Removing the visible file alone is insufficient. Maintainers should stop affected
publication, assess the scope privately, and determine applicable notification
and remediation obligations before describing an incident as resolved.

There is no promised response SLA at this stage. The reporting route is a channel
for triage, not permission to send secrets or access someone else's account.

See [publication safeguards](docs/publication.md) and [privacy requirements](docs/privacy.md).
