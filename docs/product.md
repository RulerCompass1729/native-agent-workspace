# 产品框架

As of 2026-10-18。以下区分用户已确认的目标与仍待验证的设计。

问题：让“原生保留、普通人体验、可控协作、隐私保护和无隐性开销”在使用时不需要操心；会话可以加入协作，也可以脱出继续独立工作。
现有机制：已检查 DeepSeek Harness 的 AgentRegistry、UiSession、UI layout、terminal owner 及 Claude/Codex subagent 调用链；相关源码见 [source register](sources.json)。
最小增量：基于 DSH 的本地桌面 demo，原生会话服务独立于窗口和协作成员关系。
不做会坏什么：将协作空间误当作会话的所有者，导致拖入/脱出重启 agent、丢失 fleet，或在共享时泄露私人历史。

本轮服务于创始人的产品与基础选型决定。范围是 macOS、本机运行、Claude Code + Codex + 一位真人；沿用已有竞调，仅补影响架构和分发的证据。当前已获准实施基本 demo 并实际使用验证；Claude/Codex 测试只用于关键原生能力，已有通过结果不重复烧 token，其余检查本地完成。主要读数是原生 session 身份能否保持、壳层额外模型调用数、未经授权的交接数。

## 产品是什么

一个供人使用的工作、学习与生活界面。人可以按自己的习惯和一个 agent 工作，需要时把另一个已有会话邀请进来。系统负责连接、呈现、交接、暂停与恢复，让用户少搬运内容、少管理窗口、少重复授权。

2026-10-20 澄清：协作空间以独立原生会话为参与者，不限定“一位 Claude + 一位 Codex”。例如两个 Claude 与一个 Codex 可以共同工作；也可以全部使用同一种 agent。每个参与者内部可自行使用原生 Teams/sub-agents。Portal 不把这些后代自动加入协作空间或直接作为广播接收方；父会话已收到的材料如何提供给其原生子任务，遵循原生行为与权限。Claude Agent Teams 不是产品协作的前提，使用它时仍必须保留其原生能力。

用户不需要先理解 orchestrator、fleet、worktree 或 MCP。开发者可以打开原生终端、协议状态和高级配置；单 agent 用户不需要看到团队配置。

2026-10-21：未来的多层/跨组协作要分别建模原生归属、空间成员和消息授权；人的观察视图不自动扩成 agent 的输入上下文。研究、成本边界及进入实现的条件见 [多层协作空间](scoped-collaboration.md)。当前仍是一个共享空间，不宣称已经支持任意原生子 agent 的跨空间直连。

Desktop 与 TUI 是同一产品中访问同一工作的两种方式。图形界面承担日常编辑、阅读、查看成果和协作；原生界面保留完整操作及实时核对入口。用户可以只用一种，也可以交替或并排使用。先打通维护者的 TUI 日用流程是交付顺序，不改变完整 Desktop 体验的目标；不能把图形界面降为终端启动器，也不能以图形包装替换原生能力。

验收单位是完整用户任务：从开始输入，到看懂进展、核对结果、必要时邀请另一个会话，最后继续独立工作。两种界面分别能发送消息，还不能证明混用时草稿、权限、控制权和会话身份正确。新增入口须解决已有流程中的具体阻塞，不能仅因为竞品有这个功能就增加实体。参见 [统一体验验收](interaction.md#统一体验验收与反馈依据)。

## 已确认的要求

| 要求 | 可检验的含义 |
| --- | --- |
| 单 agent 完整体验 | 一会话一 agent、一窗口一会话都好用；无 Git 仓库也能开始 |
| 原生保留 | 保留用户选择的 runtime、原生上下文、权限、配置和实际支持的 fleet；不以替换 harness 冒充接入 |
| 多个独立会话平等参与 | 首批支持 Claude/Codex 两类原生 agent，可有多个 Claude、多个 Codex 或混合；每个会话均可直接操作，不设永久主持人或强制角色 |
| 完整 Claude Teams | 验证 teammates、共享任务表与成员消息；SDK 普通 subagent 不算通过 |
| 原生 Codex fleet | 保留子 agent 生命周期、事件与原生控制；顶层任务完成不等于全部后代已停 |
| GUI/TUI 混用 | 指向同一底层会话；切换不重启、不复制、不自动重放历史 |
| 会话自由加入/退出 | 改变协作关系，保留 session；外部进程接管单列兼容范围 |
| 人掌控协作 | 人能指定接收者、暂停、改方向；旧排队消息不能在接管后继续派发 |
| 无人值守 | 有限授权内继续；到完成条件、权限边界或协作上限就停；电脑睡眠不等于任务仍在执行 |
| 隐私 | 不自动广播历史、不转存原生凭据；共享范围与实际执行权限分别处理 |
| 无隐性开销 | 默认不加模型路由/总结/标题/心跳调用，不重复发送完整上下文；按同等原生任务比较 |
| 灵活演进 | 能声明 provider 能力、选择增强或屏蔽；未知事件可查看，能力缺失要说明 |
| 普通人和开发者都能用 | 键鼠、输入法、读屏及基本可访问性；菜单有对应动作，不以大量快捷键替代交互 |
| 平台 | 首发 macOS 本地；进程、凭据、窗口、路径等平台差异有接口边界 |

## 不把绝对口号当作已解决的问题

保持原生运行时，不代表能给所有未来功能自动生成完美 GUI；需要能力探测、原生入口及版本兼容验证。

同一会话保留上下文，就可能记得之前房间的信息。退出不是遗忘，跨房间移动也不是上下文清洗。强隔离需要新的原生会话或上游提供的隔离能力，界面不得谎称两者兼得。

原生 agent 自主调用工具、发起网络请求或启动 fleet 的行为，不能仅靠房间成员表约束。UI 隐藏不等于关闭能力；权限必须由实际 runtime/sandbox 执行。对暂时无法强制的限制，不能标为硬保障。

零额外模型调用可以测；精确相同 token 总量、零毫秒延迟以及完整 fleet 的金额硬上限不能凭架构宣称。计量缺失显示未知，不显示零。

## 第一条使用故事

用户已经和 Claude 整理一份学习材料；把已有 Codex 会话加入一个协作空间，只分享指定材料与待核查的问题。Codex 给出来源和疑点，Claude 修订。用户把 Claude 脱出，在同一原生 session 继续自己的笔记；协作空间保留之前的核查记录，不再向 Claude 派发新工作。

先用这条流程验证省力与保真，再扩展到更多 agent 和任务。用户不承担逐款试用竞品的工作。

## 首版设计建议，尚非最终选择

- 一个原生 session 同时最多接受一个房间的自动任务路由；可以有多个观察视图。为降低跨房间隐私与写入冲突，先不做多个房间同时指挥同一 session。
- 首次邀请选择任务和共享内容，之后在授权范围内沿用；范围扩大再提示。
- 默认一轮核查结束；持续协作是明确打开的任务模式。
- 应用内托管会话优先实现无缝移动。外部会话按 adapter 支持区分实时连接、停止后恢复和仅导入历史。

这些建议需要技术证明与实际交互评审；不缩减用户对最终会话移动能力的要求。
