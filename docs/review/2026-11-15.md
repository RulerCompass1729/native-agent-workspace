## Temporary cleanup must keep the path to a protected profile (Codex D finding on 162db425)

**Finding (Codex D review, blocking).** A test creates an ordinary owned
directory, points TMPDIR at it and makes a `test-scratch` profile inside it.
When the scratch helper refuses cleanup (its process census fails) or the worker
is killed with SIGKILL, the worker exit cleanup or the suite parent's
reconciliation removed the owned parent recursively, taking the protected profile
and its sentinel with it, and then reported `TEMP GUARD: PASS after=0`. Both
cleanups skipped only the delegated record itself, not the directories that hold
it.

**Fix.** `scripts/fixtures/test-temp.cjs` gains `guards(records)`: while a
delegated directory may still exist (a failed lstat other than ENOENT counts as
existing), no owned directory that holds it or lies inside it is removed. Worker
exit cleanup reads every journal of the run, so a profile delegated by another
process (a child) also protects the worker's own directory; when the receipts
cannot be read, the worker removes nothing and leaves the directories to the
suite parent. `scripts/test.cjs` applies the same guard before reconciliation,
reports each kept directory as `TEMP PROTECTED`, retains the suite scope and
fails. Normal runs are unchanged: once `test-scratch` removes its profile, the
directories around it are removed as before.

**Red → green.** Three new tests in `app/tests/test-temp-cleanup.test.cjs` use
synthetic sentinels only: a refused process check, a killed worker, and a
child-process profile inside the worker's directory. On 162db425 all three fail

after=0 created=2` with the profile gone. With the fix: 9 / 0 / 0 skip. D's two
probes rerun against the lane: both exit 1, profile and sentinel kept, parent
