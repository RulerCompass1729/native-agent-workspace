## An edited queued Claude prompt showed twice in 对话

**Trigger / owner.** The person, 11-15: 「这个应该是个 bug」. A prompt typed in a
Claude terminal while a turn runs waits in native's queue; pulled back with ↑,
edited and sent again, the native terminal shows only the edited prompt, while
对话 showed both. NAW 派活, lane/claude-dup-edit-20261115.

**Cause (source).** On 2.1.323 the row comes from the UserPromptSubmit settings
hook, which fires once per enqueue (adapters.cjs, `-q<tag>` rows, T-138); nothing
in NAW read native's later `queue-operation` rows. Native journals ↑ as `popAll`,
picking one as `popOne`, and a cancel as `remove` / `cleared_on_cancel`, each
with the prompt's text (bundle 2.1.321–2.1.323; measured on 2.1.323).

**Fix.** The adapter notes the journal size when a prompt's turn begins and, at
the next UserPromptSubmit, Stop or StopFailure, reads this session's queue rows
written since (bounded, 8 MiB, no symlinks, owner-checked). A typed row whose
every enqueue was taken back is withdrawn; workspace removes it unless it already
heads a turn. Without a known window (a restarted adapter) nothing is removed.

**Evidence.** New unit test `claude-queue-withdrawn` (hand-written journal,
made-up text): main 5 fail / 5 pass, lane 10 pass. Live script
`scripts/test-native-queue-edit.cjs` (real Electron hidden, real Claude 2.1.323,
