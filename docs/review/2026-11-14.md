## The person's own send survives terminal typing and goes in beside a native draft (2026-11-14, NAW dev (continued))

The person, 2026-11-13: 「对于 Claude 和 codex 这样支持的,我希望两边的输入可以不要锁定」. Dispatch from 大管家
(follow-up to Open (B) and (D) of "The conversation box and the native terminal no longer lock each
other's input", 2026-11-13): 「用户自己的发送不被用户自己在终端的打字撤回；「人接管」对 agent/队列发送的保护不变」,
and for (D) 「先在隔离 profile 用真 Claude CLI 核 plugin prompt.submit 会不会保留原生草稿…保留就放开拒绝」.
Branch `lane/claude310-send-guard-20261114`, based on 99de2ebe (that lane is not in main yet).

**Cause.**
- (B) Every key typed in the native terminal raises `controlRevision` (`workspace.cjs` input). The
  send guard of the person's own message from the box compares `controlRevision` with its value at
  send time, so a key typed while the native side had not yet taken the send withdrew it
  (`error.submissionRevokedByHuman`, the row 结果未确认, the text back in the box).
- (D) The Claude mod refuses any message while the native prompt holds text
  (`register.js` listen and `takeMidturn`, status `draft` → `error.submission.nativeDraft`), so the
  person's own send from the box waited until they cleared or sent the terminal draft.

**Change.**
- (B) `workspace.cjs`: a new in-memory `terminalKeys` count per session rises with each key the
  person types in the terminal (`input`, the same place as `controlRevision++`; not keys an agent
  types there in a background operation). `ownControl(s)`
  accepts a control change made only of those keys. The person's own private messages use it:
  `send` (no route, forward, dispatch, wake ticket, capacity recovery or mobile session, and not in
  a background operation), private `queue` and private `steer`. Everything else keeps the plain
  `controlRevision` check, so a key still takes back a NAW queue item, a handoff, a space message or
  any automatic send. Any other control change still takes back the person's own send: a takeover,
  an interrupt, stop/restart, and a turn they submit in the terminal (`workspace.cjs` ~945 raises
  `controlRevision` without `terminalKeys`).
- (D) Measured first, then changed. Probe: the real Claude Code binaries 2.1.319, 2.1.321, 2.1.322 and
  2.1.323, each with an isolated `CLAUDE_CONFIG_DIR` and `HOME`, a loopback fake Messages API (no paid
  model call) and one probe mod. With `DRAFTKEEP typed in the terminal` typed in the native prompt
  and not sent, the mod submitted two turns with `prompt.submit({ asUser: true })`, each with no root
  turn running, and appended a message mid-turn with `session.append` at a Read tool boundary. On all four versions the prompt
  still held the draft after each submit (same text, cursor 31), before and after the append (the
  append was stored with a uuid), and about 6 s after the last turn; the submitted and appended texts
  reached the model, the draft never did. So:
  - `register.js`: `draftRefuses($, message)` replaces the five draft checks (listen's mid-turn
    pre-hold, the ordinary path before and after `/authorize`, `takeMidturn` twice). A message marked
    `own: true` is not refused for a draft on the measured versions (`draftKeptVersions`) when it
    goes in as its own turn with no root turn running (`rootIdle`) or as a mid-turn append at a tool
    boundary: the two paths measured. A submit while a root turn runs (Claude queues it natively) was
    not measured and is still refused (independent review 1, B1). Every other message, and every
    message on another or a legacy-only version, is refused as before. A held mid-turn message keeps
    its `own` mark.
  - `claude-submit.cjs`: a guard marked `ownInput` sends `own: true` with the message; nothing else
    does. `workspace.cjs` marks the guard of the person's own `send` and private `queue` (same
    condition as (B)). Steer is Codex's (`adapters.cjs` ~2377), not the mod's, so it carries no mark.
  - `claude-compat-plugin.cjs`: the previous hook file (main d7264c70) is pinned as an exact earlier
    copy, so an installed old mod upgrades; `legacy-input.test.cjs` lists d7264c70 (without the pin,
    2 tests fail).
  - The queue dispatcher is unchanged: it still reads a `draft` refusal of a queue item as 人在打字
    (`queue-dispatch.cjs` ~2614) and waits, because queue items never carry `own`.

**Checks (author-run, no model).**
