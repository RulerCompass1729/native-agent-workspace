## The person's own send survives terminal typing and goes in beside a native draft (2026-11-14, NAW dev (continued))

The person, 2026-11-13: 「对于 Claude 和 codex 这样支持的,我希望两边的输入可以不要锁定」. Dispatch from 大管家
(follow-up to Open (B) and (D) of "The conversation box and the native terminal no longer lock each
other's input", 2026-11-13): 「用户自己的发送不被用户自己在终端的打字撤回；「人接管」对 agent/队列发送的保护不变」,
and for (D) 「先在隔离 profile 用真 Claude CLI 核 plugin prompt.submit 会不会保留原生草稿…保留就放开拒绝」.
Branch `lane/claude310-send-guard-20261114`, based on 99de2ebe (that lane is not in main yet).

**Cause.**
- (B) Every key typed in the native terminal raises `controlRevision` (`workspace.cjs` input). The
  send guard of the person's own message from the box compares `controlRevision` with its value at
  send time, so a key typed while the native side had not yet taken the send withdrew it
  (`error.submissionRevokedByHuman`, the row 结果未确认, the text back in the box).
- (D) The Claude mod refuses any message while the native prompt holds text
  (`register.js` listen and `takeMidturn`, status `draft` → `error.submission.nativeDraft`), so the
  person's own send from the box waited until they cleared or sent the terminal draft.

**Change.**
- (B) `workspace.cjs`: a new in-memory `terminalKeys` count per session rises with each key the
  person types in the terminal (`input`, the same place as `controlRevision++`; not keys an agent
  types there in a background operation). `ownControl(s)`
  accepts a control change made only of those keys. The person's own private messages use it:
  `send` (no route, forward, dispatch, wake ticket, capacity recovery or mobile session, and not in
  a background operation), private `queue` and private `steer`. Everything else keeps the plain
  `controlRevision` check, so a key still takes back a NAW queue item, a handoff, a space message or
  any automatic send. Any other control change still takes back the person's own send: a takeover,
  an interrupt, stop/restart, and a turn they submit in the terminal (`workspace.cjs` ~945 raises
  `controlRevision` without `terminalKeys`).
- (D) Measured first, then changed. Probe: the real Claude Code binaries 2.1.319, 2.1.321, 2.1.322 and
  2.1.323, each with an isolated `CLAUDE_CONFIG_DIR` and `HOME`, a loopback fake Messages API (no paid
  model call) and one probe mod. With `DRAFTKEEP typed in the terminal` typed in the native prompt
  and not sent, the mod submitted two turns with `prompt.submit({ asUser: true })`, each with no root
  turn running, and appended a message mid-turn with `session.append` at a Read tool boundary. On all four versions the prompt
  still held the draft after each submit (same text, cursor 31), before and after the append (the
  append was stored with a uuid), and about 6 s after the last turn; the submitted and appended texts
  reached the model, the draft never did. So:
  - `register.js`: `draftRefuses($, message)` replaces the five draft checks (listen's mid-turn
    pre-hold, the ordinary path before and after `/authorize`, `takeMidturn` twice). A message marked
    `own: true` is not refused for a draft on the measured versions (`draftKeptVersions`) when it
    goes in as its own turn with no root turn running (`rootIdle`) or as a mid-turn append at a tool
    boundary: the two paths measured. A submit while a root turn runs (Claude queues it natively) was
    not measured and is still refused (independent review 1, B1). Every other message, and every
    message on another or a legacy-only version, is refused as before. A held mid-turn message keeps
    its `own` mark.
  - `claude-submit.cjs`: a guard marked `ownInput` sends `own: true` with the message; nothing else
    does. `workspace.cjs` marks the guard of the person's own `send` and private `queue` (same
    condition as (B)). Steer is Codex's (`adapters.cjs` ~2377), not the mod's, so it carries no mark.
  - `claude-compat-plugin.cjs`: the previous hook file (main d7264c70) is pinned as an exact earlier
    copy, so an installed old mod upgrades; `legacy-input.test.cjs` lists d7264c70 (without the pin,
    2 tests fail).
  - The queue dispatcher is unchanged: it still reads a `draft` refusal of a queue item as 人在打字
    (`queue-dispatch.cjs` ~2614) and waits, because queue items never carry `own`.

**Trade-offs.**
- Only the person's own private messages change. Forward, space, mobile, dispatch, wake, capacity
  recovery and background operations keep the old rule.
- The private reply scope that a forward opens is still tied to `controlRevision`, so a key in the
  terminal still closes it, as before.
- `terminalKeys` is never pruned (one number per session, in memory only, gone at restart).
- 2.1.307–2.1.318 keep the refusal: those binaries are not installed here, so they were not measured.
  A new Claude version also keeps it until it is measured and added to `draftKeptVersions`.
- The mark rides on the guard function (`guard.ownInput`) through the adapter, so adapters that do
  not read it (legacy Claude, Codex) are unchanged and fail safe.

**Open.**
- Not run with a real model or with the real Claude binary inside NAW. The mod decision was measured
  in the CLI with a loopback API; the GUI path ran on the fixture terminal. Daily-use acceptance
  after install: send from the box, type in the terminal before it lands; send from the box with a
  draft in Claude's prompt while Claude is idle, and check the draft is still visible in the
  terminal afterwards (the probe read it through `prompt.read`, not from the screen).
- While a Claude turn runs, the person's own queued message still waits for a native draft (B1).
  Lifting that needs a probe with a slow reply so the submit lands mid-turn, including Esc while it
  is queued natively.
- The fixture change (`scripts/fixtures/loading-terminal.cjs`) only adds the hold, release and dispatch
  methods and a second synchronous guard read before a send is recorded; the other GUI scripts that
  load it were not rerun (the shared GUI slot was taken).
- Cross-module (service, submission channel, Claude mod), so independent review before READY.

**Independent review 1** (fresh headless session a4ea3050, Read/Grep/Glob only, no MCP, tool inventory
checked; the CLI reported model claude-opus-5-5; 44 turns, 381 s, USD 2.55; diff sha256 prefix
63e10657; HEAD 99de2ebe, index tree 2b630bdf and the diff unchanged after). Verdict FAIL, one blocking
finding:
- B1 (blocking, fixed). A private queue message from the box while a Claude turn runs, with a draft
  in the native prompt, on 2.1.319 or 2.1.321 (no mid-turn append) or 2.1.322/2.1.323 when the append
  is not granted: the mod skipped the draft check for `own` and called `prompt.submit` during the
  running turn, which Claude queues natively. The probe never submitted while a turn ran (its fake
  API answers at once), so the draft was not shown to stay there. Reproduced as 4 mod tests, which
  fail on the reviewed mod and pass after the fix: `draftRefuses` lifts the refusal only with no root
  turn running or for a mid-turn append (see Change).
- N1 (fixed). `terminalKeys` also counted keys typed under a background operation, so an agent typing
  into the terminal no longer took back the person's pending send. Now only keys typed outside a
  background operation count; a new assertion in `workspace.test` fails on the reviewed code and
  passes now.
- N2 (kept). Designating the butler sends its duty text (`main.cjs` ~1962) through `send`/`queue`
  as the person's own, so it now survives terminal keys and goes in beside a draft. The person's
  click starts it and it was already treated as their composer input.
- N3 (kept, in Open). The probe read the draft through `prompt.read`; whether it stays visible on
  screen goes into the daily-use acceptance.
- N4 (fixed). The unit logs had run on an earlier version of the test files; the numbers above are
  from the final test files on the final, base and reviewed code.

**Independent review 2** (the same session a4ea3050, resumed with only the delta from index tree
2b630bdf to 7f69edf7; tools checked again; 7 turns, 83 s, USD 3.19; HEAD, index tree 7f69edf7 and the
diff sha256 prefix f32b5d9e unchanged after). Verdict PASS_WITH_NOTES. B1 is closed: the ordinary path

refused. N1 is closed with nothing else on that line changed; the record's numbers match the logs.
Notes, kept:
- `rootIdle` turns true only after the Stop hooks of `turn.complete` finish, so for that moment an own
  send beside a draft is still refused (the old behaviour, on the safe side). Watch for it in daily
  use right after a turn ends.
- On 2.1.319 and 2.1.321 `rootIdle` relies on root `turn.start` firing; the turn records already
  depend on it there (`register.js` ~803), this probe did not check it again.
