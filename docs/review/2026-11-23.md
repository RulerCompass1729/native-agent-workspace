# Review records 2026-11-23

## Confirmation cards: the asking agent hears expiry; archived sessions' cards settle

Report: an agent that asked for a confirmation heard the person's confirm or cancel, but nothing when the card ran out unanswered, so the person had to come back and ask. A click after the deadline was told as "confirmed". Cards asked by a session that was later archived could no longer be confirmed, yet stayed waiting where no view showed them.

Fix (343933bd, 37f36768):
- When a card runs out, the agent that asked is told once through the existing answer notices, with the line "人没在时限内答复，卡已过期" and the receipt state. The line does not say whether anything ran. A late click is told as expired.
- A card that has a later card for the same request stays quiet. A card asked again after the same request ran out is also not told, so an agent re-asking while the person is away is not woken every ten minutes.
- In the confirmations projection, a waiting card whose asking session is archived under the same native id is settled as invalidated, with the new reason "originator-archived" (zh and en). Missing, unavailable or other-native-id snapshots leave it waiting. Restoring the session does not revive the card.
- The notice heading now reads "你在等人答复的操作有了结果：" instead of "人已经答复：", because an expiry is not an answer.
