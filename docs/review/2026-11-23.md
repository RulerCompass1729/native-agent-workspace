## R121 (a): attach a space's shared notes to queued work (lane/claude-space-role-20261123)

The person chose (a) on 11-23. One independent read-only review covered both the wording and the behavior, 619b302b..27acf4cc. The reviewer did not write the patch, and its tools were Read, Grep and Glob only. It returned BLOCK with two findings. Both were reproduced and fixed in 1af73e04, and the same session passed the delta.

- **B1 (blocking, fixed).** Trigger: the switch is on and the notes contain control characters that the workspace send refuses (`\x01`–`\x08`, `\x0b`, `\x0c`, `\x0e`–`\x1f`, `\x7f`). The notes field allows them.
  - Impact: every queued item in the space fails, and the notes are attached again each time.
  - Fix: dispatchText removes those characters from the copy of the notes it sends. The new test failed before the fix and passes after.
- **B2 (blocking, fixed).** Trigger: notes A, then B, then back to A.
  - Impact: A was not sent again, because notesDue matched any earlier delivery of the same version. The member kept working from B.
  - Fix: notesDue compares only with the last notes delivered to that native session. A new A→B→A test failed before the fix and passes after.
- **Not changed (non-blocking).**
  - No type check on the queue field notesSent. The item validator rejects the whole queue on a bad field, and a malformed value is only compared against a hash.
  - The suggestion to say on the consequence line that only the person can change the notes while the switch is on goes to the project manager and the person, with the pictures.
  - A member can get the same notes twice: when the queue has pruned the row that carried them, or when an item is settled before its delivery tag is recorded.
- **Checked and found as described.**
  - Both note entry points require the person's own window. Merging, clearing history and phones cannot reach the switch.
  - Timing matches the request: the first item after the switch is turned on or after a member joins, then the next item after a change; nothing is sent on join or after the switch is turned off.
  - Only the notes are cut at the send limit.
  - The dialog keeps a switch changed during Save. The consequence line describes the checkbox, and it is absent while the switch is off.
