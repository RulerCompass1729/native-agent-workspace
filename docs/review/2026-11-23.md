# Review records 2026-11-23

## Resumed Claude sessions not bound to NAW after a backend move

**Report.** Two Claude sessions were moved into a reused backend slot and resumed. Afterwards their plugin refused every NAW tool locally. The backend saw no turn, and NAW kept showing them as working.

**Cause (source plus live process evidence).** The bind was never attempted. It was neither a failed `/root-bind` nor a closed channel stopping the plugin.
- The restarted backend was still checking the installed Claude version when the sessions resumed.
- So `qualification.launch()` approved nothing, and the session started the newer version with an empty `NAW_CLAUDE_QUALIFIED_VERSION`.
- With that empty value the plugin listens without binding the root, for the life of the process (`app/tests/claude-auto-update.test.cjs` already shows this at mod level).
- Another backend of the same app code had already passed the same binary.

**Fix.**
- `checkOnce` takes another backend's passed record of the same code basis, reference and binary identity, synchronously, before the restarted daemon listens.
  - This backend's own current failure wins.
  - Any other backend's current failure (other than timed-out or cancelled) means checking here.
  - Only regular files of this user, beside `backends/<20-hex key>`, are read.
- `switchBackend` resumes moved Claude sessions only after the restarted backend's own in-flight check settles. The wait is bounded by the check's limit of 5 min 20 s.
- The backend marks a Claude root that received input but did not bind within 30 s (`nativeUnbound`). The butler gets one `failure` event per occurrence, which is not repeated after a restart.
- The plugin and all authorization gates are unchanged.

**Tests.**
- Red on the base: sibling tests fail 2 of 5 there, and 3 of 5 on the first lane commit; wait tests fail 2 of 36 on the old `backend-switch.cjs`; unbound-report tests fail 3 of 4.
- Green: 45/45 in the changed files; related suites 5639/5639.

**Independent review.** A headless non-author session, Read/Grep/Glob only, no MCP servers.
- Round 1 failed on one blocking finding: with no other backend's pass, a resume during the restarted backend's own check still launched unbound.
- Round 2, over the delta that adds the bounded wait, passed with no blocking findings. HEAD, index and worktree were unchanged after each round.

**Open, not blocking.**
- The wait holds the whole move, including Codex sessions and window reconnection, for about one check (up to 5 min 20 s) when no other backend has passed.
- A resume outside a move during a check (for example the person reopening an ended session) is covered only by the butler event.
- A check aborted by a binary change leaves its `checking` record, so a move then waits out the full bound.
- Not verified: the other provider's sessions in the same incident; a live move in an isolated profile.
