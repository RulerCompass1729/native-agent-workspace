

## Codex D — PF16 isolated main/backend CPU attribution and one delta fast path

Task: profile the remaining multi-session/state-push cost after PF01/PF02 and
repair at most its largest safely small item. Base is main 96b56e89; only the
private profiling copy includes PF01's reading-list and PF02's sidebar changes,
verified byte-identical to their delivered files. Every window was hidden and
non-focusable, every native transport synthetic; daily processes were untouched.

Forty sessions with 500 synthetic replies each, 50ms updates, 20s samples:
backend state-frame encoding/delta path sampled 529.5ms inclusive
(`state-delta.cjs:97` at baseline), checkpoint persistence 301.6ms
(`workspace.cjs:407`), and main hidden-session projection 187.6ms
(`shown-sessions.cjs:34`, of which messageSummary 167.4ms). These are distinct
call paths, not parent/child costs added together. V8 sampled stack time is not
the entire process's user+system CPU usage. Smaller-history ranking differs;
no claim is made about the unobserved daily profile.

Only the largest path is changed: when the encoder carries the same immutable
digest array, take its whole length without re-comparing every element. Live
message-array identity grants no shortcut. Existing rehash, two-second fallback,
changed hints, protocol, old clients and backpressure/base rules are preserved.
The new regression observes digest-array reads: old 4000 versus expected zero
for 2000 unchanged messages (12/1/0); repaired 0 reads and 13/0/0, plus in-place
edit/new-digest exact reconstruction. Related state/delta/transport/push/client
checks are 169/0/0, temporary residue 0. Full suite not run.

Three paired isolated runs average backend CPU 10.16% to 9.65%, main 6.49% to
6.76%; combined 16.65% to 16.42%, too small to claim whole-window improvement.
The last pair counted 80 page-state frames on each side. Original and repeated
CPU outputs, profiles, the workload and top-three analysis are private. This
repairs verified repeated comparisons, not all of PF16. Daily main 10–20% and
real-user input latency were not reproduced/verified. No second hotspot,
reminder/bell code, UI/layout, installation, push or model review is included.
The shared protocol increment remains for independent batch review.
