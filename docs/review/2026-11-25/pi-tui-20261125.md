# pi on DeepSeek as a terminal member (R246)

The person, 2026-11-25: 「pi 要装,放真 DeepSeek 测试和使用」. The earlier research (private report, archived) identified pi as `@earendil-works/pi-coding-agent` 1.6.1 (MIT), read its network paths, and found that without switches it sends every `AGENTS.md`/`CLAUDE.md` from the working folder up to `/`, and the person's skills, with each request.

- New provider `pi`, terminal-only, built like the DSH TUI: NAW's PTY with only a listed environment, the macOS sandbox allowing only NAW's loopback egress proxy, the proxy passing only `api.deepseek.com:443`, the witness stopping the session on any refusal, the key from the DSH Keychain item into the child's environment only (`app/pi-tui.cjs`, which reuses `dsh-tui.cjs`, `dsh-egress.cjs`, `dsh-witness.cjs`).
- pi runs with `--offline --no-context-files --no-skills --no-prompt-templates --no-extensions --no-mcp --no-approve`, `PI_OFFLINE=1`, `PI_TELEMETRY=0`, `PI_SKIP_VERSION_CHECK=1`, its own HOME and agent folder, and NAW's session folder. The sandbox also refuses reads of the person's `~/.pi`, `~/.claude`, `~/.codex`, `~/.agents`, `~/.dsh`, `~/.dsh-tui`, `~/CLAUDE.md`, `~/AGENTS.md`.
- NAW chooses pi's session id at creation (`nativeId`), so a restored record opens the same pi session.
- The runtime is installed once per NAW data folder (`<data>/pi-tui-runtime/1.6.1`, every backend uses it) by `scripts/install-pi-tui.cjs` from the committed lockfile (123 packages, all npm public registry with sha512; pi's own integrity pinned in code). The install never replaces an existing runtime. Each start checks versions and that every one of its 17,614 entries is the person's and not group- or world-writable, with in-tree links only (about 0.1 s).
- The installer runs `npm ci` inside the folder: npm 11.20 with `--prefix` fails with "Missing: runtime@ from lock file". The same happens to `scripts/install-dsh-tui.cjs` (reproduced with its lock and `--dry-run`); not changed here.
- Wiring: provider lists and labels (workspace, background summary, renderer, search, reading list, coordinator context), the create window's pi choice (shown only when the service reports the runtime), the private runtime module list and the app bundle list, messages in both languages, privacy/readiness/licensing sections.

## Limits

- Not reachable from spaces, queues or other sessions (`chatAvailable` false, as for DSH).
- pi has no per-tool approvals.
- Any non-DeepSeek connection by a command pi runs stops the session.
- pi's `find`/`grep` tools need `fd`/`ripgrep`, which offline pi does not download.
- Not run: the installed app, long sessions, compaction.
