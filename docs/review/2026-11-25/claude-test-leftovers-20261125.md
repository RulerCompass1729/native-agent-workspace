## A stopped test run ends what it started (lane/claude-test-leftovers-20261125)

On 11-25 eight process trees of earlier test runs were still on the machine, some for fifteen hours. Four came from full runs that were stopped: two services of `operator-bootstrap.test.cjs`, the stopped (SIGSTOP) worker of `claude-version-lifecycle.test.cjs` with its version program, and the detached process of `codex-stop-processes.test.cjs`. Their cleanup is in `t.after`, which a stopped run does not reach, and each is in its own process group. Finished runs left none. One was a test file itself: `computer-use-outbox-claude.test.cjs` opens its listener before it registers any cleanup, so when its fixture throws in between, its process never ends.

`scripts/test.cjs` now ends them, before it removes the run's directories (`scripts/fixtures/test-processes.cjs`, rules in `docs/testing.md`). One place instead of each test, since every test that starts a service or a detached process has this hole and a killed worker cannot run its own cleanup. On this machine the rule found exactly the four and no other process. The outbox test registers its cleanup as soon as the listener is open.

Tests: five in `test-temp-cleanup.test.cjs`; on 294d1609 all five fail. With the real files, stopped by SIGTERM and by SIGINT: before, `codex-stop-processes` left 4 processes (one for good), `operator-bootstrap` 1, `claude-version-lifecycle` 2; now 0. The outbox file with a fixture that throws: before, its process was still there after 12 seconds; now the file fails and ends in 0.3. 100/100 in six related files, and 148/148 through `scripts/test.cjs` in eleven (the nine that start a service among them), where the new check says nothing. 11 edits that break the rule: 10 fail at least one test; the other, the start time not compared, needs a process ID taken by another process between two reads, which no test did (see below). Not tested: Linux (only the command is read there), a full run.

Limits. `node --test` called directly, and a run that is killed outright, end nothing. A shared daemon that a test starts by accident would carry the run's directory too and be ended; none was found. A leak does not fail a finished run yet: to be turned on after a few full runs that show none.

Narrowed after review (on 7f62a819). A process that the run did not start was ended too when it had no owner and its command named the directory: a `tail` someone left, an editor opened there. By its command only node and Electron count now, recognised by the kernel's name for the program. An environment counts for any program, except `PWD` and `OLDPWD`, which only say where a shell stood: an editor opened from there has them. The price: macOS does not show the environment of its own programs, so a shell or a `sleep` that a test leaves without an owner stays, with what it started. `test-process-guard.test.cjs` runs the rule over a made-up process list with a stubbed `process.kill` (13 tests): the two looks at the start time before each signal, and which processes count. On 7f62a819 four of them fail, and a real `tail` in `test-temp-cleanup.test.cjs`; the start time was compared there already, and without it two fail. 14 edits of the rule all fail at least one, run in that file alone, so that nothing real is signalled. The three real files, stopped, still leave 0.
