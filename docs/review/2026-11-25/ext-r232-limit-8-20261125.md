# Eight automatic messages an item

The person asked on 2026-11-25 that automatic messages between agents be allowed up to eight for each item. NAW refused the fourth from one sender to one recipient until the person typed in the recipient or, for the butler, the member's own message to it was delivered.

- The limit for each sender and recipient is eight in place of three. Both refusal texts say so in both languages. The minute between messages, the person's reset and the butler's reset by a delivered answer stay.
- When NAW records an item as done, whoever queued it, the dispatcher tells the backend of the member that had it and the backend of the butler, once and after the record is saved. The member's backend clears every sender's run to that member; the butler's clears the member's run to the butler. Each checks the exact native session, saves, and takes the clear back if it cannot save. Every other direction keeps its run.
- Nothing is cleared for an item that is waiting, failed, cancelled, marked handled, or answered from its card. A backend without the method keeps its limit: after an update, one still running the older version keeps three.

This replaces the earlier lane that cleared only the butler's run after an item the butler queued (`5b7dbbab`, not merged).

## Bounds

With no input from the person, a pair stops at the ninth message without an item done in between. With k items done by a member M: any sender has at most 8(k+1) messages to M, M at most 8(k+1) to the butler, and the butler at most 72(k+1) to M, because a delivered answer from M also clears the butler's run (12(k+1) at the old limit of three). Each is a minute apart. `session-wake-loop-bound.test.cjs` checks these against the real clear, keeps every earlier case with the number changed, and holds the number in the test itself.

## Checks

Commands, counts and outputs are in the private record of the lane. The tests were written first and fail on the unchanged code; changing only the number leaves the item tests failing. No model was called, no window was opened, and the daily app was not touched.

## Known limits

- The number of items is not limited by program, as before. A secretary may queue an item for itself; each one that is done allows up to eight more messages to it and from it to the butler.
- If NAW stops between recording the item and the call, or the call fails, the run stays until the next item, the person or the member's message clears it. A call that timed out may still clear it later.
- "Once an item" rests on the recorded status in the main process; the backend receives no item id.
- Between members, and from a member to a space's project manager, the limit is eight until an item the recipient had is done.
- The refusal still says that a person must check the original session, though an item done there also clears it.
- Not checked in the daily app.
