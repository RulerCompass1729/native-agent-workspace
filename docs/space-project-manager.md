# 空间项目经理

状态：2026-11-25，源码已实现，未装进日常版。下面写的是代码现在的做法；没做到的列在最后。

用户 2026-11-23 的原话：

- 「项目经理是每个协作空间都有的,只负责这个协作空间的主题有关 d 任务,而不是全局的.
  之前可能有"秘书"这个角色但是需要退役掉,保证每个协作空间有个自己项目经理进行工作推进.」
- 「每个协作空间的项目经理不能完全靠 prompt 来做,我觉得需要用一部分NAW 的设计来保证
  不会让项目经理被其他空间的任务干扰」
- 「新建的空间自动开项目经理,自动安排一个项目经理」

权限怎么划、秘书怎么退役这两件，用户没有直接答；下面是大管家按原话的读法，用户可以改。

## 角色

- 一个空间最多一位，一个会话最多管一个空间。记录在 `space-managers.json`
  （`app/space-managers.cjs`），只有真人能指定、换人、撤销；agent 和大管家的调用都被拒。
- 要先是这个空间的成员，会话正常可用，不是大管家，不在轮换中途。离开空间，角色就不起作用，
  回来又起作用。
- 会话轮换时，跟随轮换日志里唯一明确的后继。接班的会话确认交接的那一刻（日志 `handed`），角色就
  转过去，`kept`、`done` 也一样；你还在用旧会话、旧会话留着没结束时也是这样。当过这个空间经理的会话
  再加任务会被拒，并写明经理现在是谁；没当过的照普通成员拒。交接之后又失败（比如接班的会话没了），
  角色回到旧会话；分叉（多个后继）不转。大管家和集成者仍只在 `done` 时跟随。
- 你手动指定的那一位立刻生效，一直算数：指定之前写下的交接（`handed`、`kept`）不会把它带走；只有
  `done`（旧会话已经结束）照常跟过去。之后再有新的交接，照上面跟过去。
- 角色到了不会再退回的会话（一路经 `kept` 或 `done`）以后，`space-managers.json` 改记这个会话，空间里
  记一句「X 接任这个空间的项目经理」，X 就是现在的经理。只经 `handed` 到达时，界面标签和加任务的权限
  已经按日志认它，记录暂不改：这段还可能失败退回，而记录要是加来源字段，旧版本会读不出。标签和权限读的
  都是 `all()`。记录的每次改动都先在轮换日志记一行：你指定是 `designated`，交接写入是 `settled`；
  旧版本读日志时跳过这两种行。
- 记录读不出来算出错，不算「没有人」：经理加不了任务；同不属于任何空间的会话、同一空间的成员
  照常，跨空间的消息先不送；空间成员的后台视图只列它自己的空间，不给正文，也不能合并空间。
  这时真人再指定，会先重读一次，还读不出来就要先确认重新开始：别的空间的经理得再设一遍，坏的那份改名留着。

| 动作 | 真人 | 项目经理 | 普通成员 | 大管家 |
| --- | --- | --- | --- | --- |
| 指定或撤销项目经理 | 可以 | 不可以 | 不可以 | 不可以 |
| 往本空间队列加任务 | 可以 | 可以，交给成员 | 不可以 | 可以 |
| 取消、标记已处理、归档、改名、管成员 | 可以 | 不可以（只能撤回自己加的） | 不可以 | 取消和标记可以 |
| 看别的空间的名字、成员、队列 | 可以 | 不可以 | 照原来的规则 | 可以，记录 |
| 看别的会话的对话 | 可以 | 不可以 | 照原来的规则 | 可以，记录 |
| 收别的空间的成员发来的消息 | 人自己选 | 拒收 | 照原来的规则 | 照原来的规则 |

## 靠什么挡，不靠提示词

| 要求 | 代码 |
| --- | --- |
| 只往本空间加 | `SpaceManagers.creator`：角色的空间和目标空间一致才行 |
| 只看本空间 | `conversationAccess` 的 `limit`；`background-operation.cjs` 按它去掉别的空间、别的会话和别的轮换链；合并预览（`spaceMerge`）拒绝；`workspace_sessions` 也只列本空间 |
| 别的空间的消息进不来 | `session-wake.cjs`：登记时和送达前各查一次；`workspace_control` 的发送、排队、插话、接力（`assertManagerDelivery`）：真人在确认卡上点过的除外 |
| 一个 agent 加的任务不会绕回来叫醒它自己，也不会叫醒别的经理 | `managerItemMayGo`：计划时和发送前各查一次，也不派给接它班的会话；角色读不出来时这类任务先等着 |
| 每次接活都知道自己的角色 | 派活文字末尾附一段角色说明；不单独发问候 |

不在任何空间里的会话（大管家、集成者、独立会话）发来的消息不拒收。

## 新建空间

两个建空间的对话框都有「自动安排一个项目经理」，默认勾上，可以取消；本机没有 Claude 时不出现。
勾着就新开一个 Claude 会话：用 Claude 自己的默认模型和权限，文件夹同上次新建会话，加入空间后
指定为项目经理，不发任何输入。没安排成不影响空间，界面说明原因，不自动重试；之后可以从空间
菜单新开，或在成员菜单里指定。新建会话时顺带建的空间，要等那个会话加入了才安排；半路停下的
不安排，也不另外提示。agent 用后台操作建的空间不自动安排。

花费：创建时 NAW 不发输入。Claude Code 2.1.332 实测，用 API key 登录时，第一次输入之前没有
`/v1/messages` 请求；用订阅登录时有一次，内容是 `quota`，`max_tokens` 为 1，启动后一两秒发出，
空闲四分钟没有第二次。所以「创建本身不调模型」对订阅登录不成立，对话框里照实写。

## 秘书退役

全 NAW 一个的秘书不再有任何权限。装上后处理一次：它只在一个空间、那里还没有项目经理，就转为
那里的项目经理，空间时间线记一行；不在空间里、在几个空间里、已归档或换了原生会话，只退役。会话
没列出来、停着、正在换上下文、轮换中已经离开空间却还没结束，或它的空间所在的后台没连上，就先
不定，等看得清再处理；停着不再开的话一直不定，装新版后的通知仍发给它。没定之前你给那个空间
设过或撤过经理，以你的为准，它不再接手。`queue-secretary.json` 只读
不写，旧版本还能读到原样。以前由秘书加的任务，来源现在显示为「项目经理 … 添加」。装新版后的
通知，原来发给秘书，现在发给接手秘书那个空间的项目经理，不发给大管家。

## 没做到、没验证

- 文件没有隔离：原生 agent 用 shell 读文件，NAW 不在那条路上，不写「文件已隔离」。
- 还在旧后台上的会话，搬到新版后台之前不挡跨空间消息，列会话时也不收窄。
- 指定之前已经排队等原生接收的消息不会再查一遍。
- 项目经理自己发给别的空间的消息不限制；它仍能像别的 agent 一样用后台操作改别的空间的笔记等
  （改不了队列），只是看不到那里的内容。
- 成员做完时，NAW 不会自动叫醒项目经理。
- 合并空间后，来源空间的记录还在，但角色不起作用。
- 没指定给谁的任务（人或大管家加的）也可能派给项目经理。
- 真机界面没有操作过：改过的 Electron 验收脚本只做了语法检查。
