# 原生会话连续性：第一轮结果

As of 2026-10-17。结论：**Codex 的空闲主会话已有真实连接证据；双 agent 的完整连续性尚未通过。** 本轮开始有限技术试验，没有桌面产品或协作房间可供使用。

## 实测范围

本机 macOS，Codex CLI 0.163.0，Claude Code 2.1.302；只对 Codex 运行了模型任务。Claude 部分是本机帮助与官方文档核查，不是 Teams 运行证明。

Codex 使用单独启动的原生 app-server、私人 Unix socket、原生认证和一个合成工作目录。测试进程关闭 analytics，未改全局配置，未提取或复制凭据。探针使用 Python 与 websockets 16.0。原生服务保留其余用户配置；因此本轮不是干净配置的性能基准。

| 检查 | 观察结果 | 裁定 |
| --- | --- | --- |
| 空线程的第二客户端连接 | `thread/start` 后出现在 loaded list，但 `thread/resume` 报找不到 rollout | 未通过；空线程不能冒充可恢复会话 |
| 有记录的空闲线程 | 一条合成任务完成后，第二个 JSON-RPC 客户端连接同一线程 | 通过本轮限定检查 |
| 原生 TUI | 在真实 iTerm2 新窗口中启动两个 `codex resume --remote`，均显示原来的合成回复 | 通过显示与连接检查；不是模拟终端 |
| 退出一个 TUI | 原生界面显示已断开；另一 TUI 保留同一回复，控制客户端仍读到同一 idle thread | 通过本轮限定检查 |
| 退出两个 TUI | 原 app-server 进程仍存活，两个控制客户端仍连接原线程 | 通过；控制客户端始终持有连接 |
| 新公开探针 | 两个客户端订阅、断开观察者后复查 ID、session-tree ID、创建时间与 loaded 状态 | 通过；不等于证明全部内存状态 |
| 未加载 ID / 非私有 socket 目录 | 探针返回 `not_passed` 和非零退出码 | 拒绝有效，无自动创建或冷恢复 |

没有把视图注册或字典中的成员变化当作“入房/脱出”实测。当前还没有房间实现。

## 用量与隐私的准确读法

为建立原生记录，本轮发送一次 `turn/start`，要求仅回复合成标记且不使用工具。原生回复符合要求。该测试实际产生原生用量：输入 19,978 tokens（其中 cached input 12,288），输出 8；不是“整个试验免费”。较大的输入含原生运行配置上下文，不代表外壳复制了会话。

后续连接与退出期间，原控制连接的 `turn/started` 与 `thread/tokenUsage/updated` 计数没有增加。公开探针不允许发送模型任务，其自身运行记录为 0 个 turn-start 请求、0 个观察到的 turn-start 事件和 0 个 token-usage 更新。**这些读数不是完整网络出口审计或账单证明，也没有建立同等任务的成本/延迟基线。**

原生响应还包含路径、账号事件、hooks/MCP 状态等。公开探针只输出选择后的结果，不打印原始响应和异常正文。原始终端与协议证据留在本地，未作为截图、日志或附件上传。两个测试 TUI 已正常退出，测试窗口保留；仅停止本轮创建的服务。原生合成会话记录由原生保留机制管理。

## Claude 为什么需要另一条验证路径

本机帮助有 `attach` 与后台会话入口。但官方说明区分了“接入已经在后台运行的会话”与“把前台会话转到后台”：后者启动新进程恢复，部分工作可能停止或重跑。相同会话 ID 不足以证明活跃状态完全保留。

官方还说明 agent view 的行摘要会调用 Haiku 类模型，并在回合结束或长回合中更新；不是全部都由本地状态拼成。本轮未找到并验证一个受支持的“只关闭该摘要推理”方案。因此它暂不作为本产品默认零额外推理路径。[官方后台会话说明](https://code.claude.com/docs/en/agent-view)

完整 Agent Teams 需要交互式 CLI，不能由普通 SDK subagent 代替；官方仍列有恢复时不恢复 in-process teammates 的限制。本轮没有启动 Claude Teams，也没有验证上述后台转移对 Teams 的全部实际行为。[官方 Agent Teams 说明](https://code.claude.com/docs/en/agent-teams)

## 架构决定与下一检查

保留现有“session 独立于 room/view”的架构。Codex 继续验证原生 app-server 路径；Claude 下一步验证**由本机 session 服务从创建时就持有同一个原生交互式 CLI/PTY**，视图移动只改变订阅，不调用后台化或 resume。PTY 是内部连接机制，用户界面不要求用户学习 tmux。

这只是下一项待验证路径，不承诺任意外部终端中的活跃进程都能被接管。外部接入能力必须按 provider 与会话当前状态区分，不能偷偷关闭原会话再启动副本。

DSH 仍是可复用界面/组件的候选，尚未引入其实现。先验证其视图生命周期不会销毁持久 session，再决定复用范围。

以下三组仍是未通过项：

- active Claude Teams、Codex fleet、工具待审批、活跃任务与控制通道切换；有保持原生进程的路径后真验。
- 房间成员变更、定向交接、单写入者、人类接管、撤销旧队列；有真实控制实现后验，不能由本探针代替。
- GUI/鼠标/输入法/草稿、断线与睡眠恢复、完整网络审计、同等任务延迟和费用；有相应表面后验。

## 复现与证据边界

[公开探针与运行说明](../experiments/native-continuity/README.md)只检查一个已加载的空闲线程。它保持方法白名单、socket 私有权限检查与失败关闭。loaded 检查和 resume 不是一个原子操作；测试必须保留原 owner，不能用于承诺并发卸载期间的无损 attach。

本轮接口还依据当前 CLI 生成的 JSON Schema 核对了初始化、loaded list、read、resume 与 turn 参数；未读到对应版本完整服务实现，故不作内部对象复用的源码结论。上游 app-server 接口仍标为 experimental。[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)

真实终端与原生服务检查，加上探针的两个拒绝用例，支持表内限定结论。它们不构成完整产品验收或未来版本兼容保证。
