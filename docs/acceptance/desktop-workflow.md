# Graphical independent-session workflow — M1

As of 2026-10-20. Alpha.44 source, installed interface and the finite native task
below passed final independent source, installed-artifact and evidence review
within the boundaries stated here.

The person provides a local text material, chooses independent participants,
reads their progress and a result, detaches a session, then reopens the workspace.
No native Teams prerequisite, fixed leader, repository or hidden model call.

## Acceptance and boundaries

- Actual Electron/DeepSeek Harness interface actions create distinct sessions,
  select exact `@` recipients, preview a file, append it to an existing draft,
  choose participants/order and approve a finite exchange. At most six root
  replies in ten minutes; joining does not activate or broadcast to everyone.
- Two-Claude/one-Codex and one-Claude/two-Codex arrangements, duplicate labels,
  excluded participants, order changes and aliases have local deterministic
  coverage. Automatic participants must share a capable backend; retained old
  sessions are not moved or silently upgraded. Native permissions, errors,
  human intervention and membership changes still invalidate handoffs.
- The selected first participant stays first. Other checked participants are
  appended in selection order and can move earlier; the exact sequence through
  the total reply cap is displayed. Changing selection/order/limit clears consent.
- TXT/Markdown/CSV/TSV/JSON UTF-8 files up to 256 KB can be viewed locally, added
  explicitly to a draft (16,000 characters total), and saved as an exact copy.
  Bounded exchanges keep a separate 6,000-character task/material limit, shown
  before authorization; longer drafts stay available for editing or directed send.
  Existing files are not overwritten. Preview is a snapshot, not a live editor.
- Delayed file selection after navigation and lost ownership cannot change a
  different session's draft. A failed save does not append a material again.
  Native file selection is controlled in the regression runner; this does not
  certify physical macOS picker, accessibility or IME behavior.
- Detach, archive/restore and UI reopen preserve native identity, received context,
  private drafts and shared records. These actions make no additional submission.

## Finite native task

Use three independent sessions, Claude Haiku / Codex Luna / Claude Haiku, with
no native subagents. The synthetic CSV is lunch: 3 × 18 and transport: 3 × 7.
The independent oracle is 54 + 21 = 75, or 25 per person. Select and preview the
CSV in the GUI, append it to a short instruction, then authorize exactly three
replies: calculation, independent check, and a small Markdown result file.
Verify the selected cheap models before dispatch; no silent default fallback.

Budget: three root submissions in one finite run. Native tool calls and internal
assistant turns are additional usage; this is not a hard monetary cap. Do not
rerun paid work for a count or appearance. If native permission intervention
invalidates room sharing, preserve that behavior and inspect the private result
and actual file. Do not reinstate an obsolete authorization.

The deterministic runner's result file is fixture-created and only proves the
preview/copy path. A real native task must provide separate evidence that an
agent actually wrote a correct result. Screenshots/recordings, raw native data
and local filesystem paths stay private; source fixtures are synthetic only.

## Observed outcome — alpha.44

The installed application completed the CSV task with three independent native
sessions: Claude Haiku 5.5, Codex GPT-6-Luna and Claude Haiku 5.5. Their models
were checked before submission. The first calculated 75 total / 25 per person;
the second independently agreed; the third used one native shell tool to create
the requested Markdown file. The file matches the independent arithmetic oracle.

The third session requested native write permission. The tester inspected its
exact command and approved that operation once in its existing terminal. This
intervention correctly paused automatic sharing: two replies reached the shared
timeline, and the final reply remained private. The test did not restore the old
sharing authorization or count this as unattended completion (A43-3).

Actual installed GUI actions then opened the result, previewed its text, saved
an exact byte-for-byte copy, dragged the final session out of the room, retained
a Chinese unsent draft, archived/restored it and reopened the application. Native
identities, received context, shared records and the draft were retained without
another submission. No renderer errors were observed. Native file-picker results
were controlled by the runner; physical picker/OS input acceptance is not added
by this check. The recording captures actual app frames, not a narrated mockup.

Usage was exactly three root submissions and zero portal-owned model calls.
Native transcripts additionally contain three Claude assistant messages in total
and one shell tool invocation; no native child was observed. The Codex turn
reported 23,053 tokens, including 11,520 cached input tokens. Claude reported
18,929 cache-creation input tokens, 46,735 cache-read input tokens, six other input
tokens and 791 output tokens across both sessions. These provider categories are
not a bill or comparable per-provider cost; native instructions and tool turns
still consume usage. No extra model task was sent to repeat a passing result.

The deterministic actual-Electron runner separately covers both three-session
provider arrangements, duplicate labels, an excluded fourth member, order,
six synthetic dispatches, length rejection, delayed pickers and failed-save
recovery. It makes zero native model calls. The source full suite passed 388
checks; after the final length-message correction, 112 affected checks and the
installed GUI runner passed. The final installed payload matched all 39 reviewed
source files. Normal user session/process identities, history and draft hashes
were unchanged before/after the isolated trial.

Final independent artifact inspection caught a test-harness error: directly
starting the installed daemon let native Claude plugin initialization generate
types inside the signed bundle, invalidating its resource seal. The reviewed
archive was restored unchanged. A separate zero-task actual GUI launch through
normal service bootstrap reached native Claude readiness, generated those files
only in the copied private runtime, and passed strict bundle signature checks
before, after and after cleanup. Native test instructions now require that path
and a post-test signature check. The earlier successful task is reused; no paid
task was repeated for the artifact repair.
